# 태그 없는 LiDAR 자동 형상 구분

## 직접 실행

1. `Content/MA0T10/Maps/Tests/LidarSemanticValidationMap`을 열고 PIE를 실행한다.
2. 같은 기본 재질의 기준 판과 이동 물체가 나타난다. 두 Actor의 Tags는 비어 있다.
3. 모니터는 `월드 XY 조감도` + **자동 형상 구분 — 태그 불필요**로 시작한다. 기준면은 파랑, 돌출점은 주황, 판단 불가는 회색이다.
4. 상단 테스트 조작에서 `CPU / GPU`, `이동 / 정지`, `형상 / 높이`, `3D 포인트`를 선택할 수 있다. CPU FullSpec은 게임 스레드 trace 예산 때문에 GPU보다 완료율이 낮을 수 있다.
5. `검증 화면 저장`은 실제 viewport 크기, 빈 태그/같은 재질 여부와 화면을 `Saved/Reports/geometry_manual.md/.png`에 저장한다.

테스트맵은 사용자 UI 보기/배치 저장값을 변경하지 않는 독립 모니터를 사용한다. 기존 운영맵, Slab 시나리오, 동료 Widget을 재생성하지 않는다. 새 맵 생성 스크립트는 `Scripts/create_lidar_geometry_validation_map.py`이며 이미 존재하는 맵은 덮어쓰지 않는다.

## 기존 맵에서 사용

LiDAR 모니터의 **표시 옵션 → LiDAR 색상 방식 → 자동 형상 구분 — 태그 불필요**를 선택한다.

- **자동 형상 구분**: 측정 XYZ만 분석한다. Actor 이름, 클래스, SemanticLabel, Tag, 재질을 정답으로 사용하지 않는다.
- **높이 색상**: 높이를 연속 색상으로 표시할 뿐 물체/판 분류는 하지 않는다.
- **태그 기반 의미 분류**: 기존 호환 기능이다. 태그나 규칙이 없으면 같은 회색으로 나올 수 있다. 이번 기능은 이 옵션과 별개다.

원본 PCD의 XYZ, 단위, 프레임 번호, Topic/schema 및 Slab 메타데이터는 그대로다. 자동 구분 결과는 표시용이며 PCD에 새로운 클래스 필드를 추가하지 않는다. 수신자는 기존 `sensor_to_world_m` 행렬로 월드 좌표를 복원해 높이를 확인할 수 있다.

```powershell
python Scripts/inspect_binary_pcd.py received.pcd --plate-z-m 0
```

## 알고리즘과 한계

- 유효 XYZ 중 최대 4,096개 대표점을 사용한 96회 고정-seed RANSAC과 최소제곱 평면 재추정.
- 주요 기준면의 기울기는 수평에서 20° 이내, 평면 허용 오차 2cm. 돌출 진입은 5cm, 이전 돌출 위치의 해제 기준은 3cm다.
- 충분한 지지점/면적이 없거나 비슷한 지지도의 다른 평면이 있으면 판을 찾았다고 가장하지 않고 **월드 높이 색상으로 대체**한다. 상태와 점 수는 범례/테스트 조작 영역에서 확인한다.
- 바닥, 테이블, 여러 단차가 섞인 장면에서 사용자가 의도한 특정 판을 항상 선택한다고 보장하지 않는다. 이 경우 관심영역 또는 별도 기준면 지정은 후속 기능이다.
- `Slab`이라는 업무 의미, 개별 물체 ID, 접촉한 물체의 분리, 추적/AI 판단 기능이 아니다. 물리 측정에 사용하는 기존 반사 모델과 별개로 분류 판단에는 재질을 사용하지 않는다.
- 분석은 기존 비동기 projection worker에서 실행한다. 처리 중 1개와 최신 대기 프레임만 유지하고 원본 측정/PCD를 기다리게 하지 않는다.

## 검증

- `MA0T10.LidarGeometry.GeometryOnly`: 태그 없는 XYZ, 기울어진 판, 수직 벽/점 부족, 모호한 평면, 히스테리시스/잔상 방지.
- `MA0T10.LidarGeometry.ActualMapPixels`: 실제 PIE에서 CPU/GPU 측정, 같은 재질/빈 태그 확인, 내부 구분 정확도, 업로드된 GPU 텍스처의 파랑/주황 픽셀과 이동 검증. 범례 픽셀을 세지 않는다.
- `Scripts/run_lidar_geometry_stream_test.ps1`: 로컬 Artemis 개발 인스턴스(61616, 개발용 기본 계정)를 사용한 10초 준비 + 60초 PCD 시험과 독립 외부 구독. Broker 설정은 변경하지 않는다.
- 증거는 `Saved/Reports/geometry_*`에 기록하고 커밋하지 않는다. 실제 수행하지 않은 GPU/성능 시험의 skip은 통과 증거로 간주하지 않는다.

이번 검증 과정에서 발견한 CPU 광선 회전도 수정했다. Euler 각도를 더하는 대신 센서 로컬 광선을 Transform으로 회전시켜 수직 설치에서 스캔 범위가 좁아지는 문제를 방지한다. 수동/자동 CPU 경로에 동일하게 적용한다.

### 2026-09-17 실행 결과와 남은 제한

- 같은 재질/태그 없는 판과 물체의 내부 구분 정확도는 GPU 정지/이동 및 CPU에서 100%였다. 실제 GPU 텍스처에서 파랑/주황 픽셀을 검출하고 주황 영역이 물체 이동을 따라가는 것을 검증했다.
- 실제 PCD를 별도 파서로 복원한 월드 Z는 약 0.0002~0.2501m로, 25cm 차이가 보존됐다. 로컬 Z 자체를 현장 높이로 읽으면 안 된다.
- PCD 제출/receipt/자체 수신은 1,400건 일치, 외부 수신 약 20Hz, invalid/gap/overflow 0이었다.
- 형상 분석 p95는 약 0.81ms였지만 이 검증맵의 에디터 성능은 평균 약 48.38 FPS, 1% low 약 33.16 FPS로 **목표 미달**이다. 형상 기능 OFF 대조군도 약 48.37 FPS였다. 이를 55 FPS 달성으로 표기하지 않는다.
- Computer Use의 초기 캡처 오류 후 사용자가 화면을 활성화해 마우스 검증을 재개했다. 실제 PIE **1180×723**에서 이동/정지, CPU/GPU, 형상/높이 전환, 3D 표시, 모니터 드래그·접기와 화면 저장을 직접 확인했다. 태그가 비어 있고 재질이 같은 상태의 파랑/주황 표시를 2D와 3D에서 확인했다. 1920×1080 마우스 검증으로 표기하지 않는다.
- 검증 전후 `MA0T10_VirtualSensorUI_v6.sav` SHA-256이 동일해, 테스트맵 조작이 기존 사용자 UI 저장값을 덮어쓰지 않은 것도 확인했다. 화면과 실행 상태는 `geometry_manual_gpu.*`, `geometry_manual_cpu.*`, `geometry_manual_3d.*`에 있다.
- 여러 평면이 섞인 사용자 실제 장면에서 원하는 판 선택, 일반적인 물체 인식, 모든 재질/동작에서의 검출 정확도는 보장 범위가 아니다.
