기본 3대는 **OS1-64 Rev7, 1024×64 / 20Hz**로 선택한다. [Ouster 공식 Rev7 데이터시트](https://data.ouster.io/downloads/datasheets/datasheet-rev7-v3p0-os1.pdf) p1의 90m는 10% 반사율·검출확률 90% 초과·100klx·1024×10Hz 조건이다. p3은 1024×20Hz 지원을 명시한다. 90m는 시뮬레이션 거리 envelope이며 같은 검출확률이 20Hz에서 보장된다는 뜻은 아니다. 수직 FOV는 ±21.2°, 최소거리는 0.5m, 균일 64 beam은 미교정 근사다. single return 예산은 프레임당 65,536점, 초당 1,310,720점이다. 공개 precision 상한 30mm를 잡음 가정으로 사용하며 실장비 교정/인증으로 취급하지 않는다.

[공식 Rev05 데이터시트](https://data.ouster.io/downloads/datasheets/datasheet-rev05-v2p2-os1.pdf) p1의 45m는 위와 같은 10%·1024×10Hz 검출 조건으로 기존 프로필이 맞다. 120m는 80% 반사율·50% 초과 검출 조건이므로 45m를 120m로 대체하지 않는다. Rev05와 XT32·Mid-360S 등 기존 선택은 그대로 둔다. Rev7 enum은 마지막에 추가하여 저장된 enum 순서를 보존한다.

기존 붐 장착점 Z=39.25m, Y=14.5m에서 홀드 먼 바닥 모서리까지 약 54.6m이므로 45m Rev05는 거리 여유가 부족하다. Rev7의 90m envelope가 충분하므로 좁은 수직 FOV의 OS2를 선택할 필요가 없다. 거리가 충분해도 개구부·구조 차폐·beam FOV가 커버리지를 제한하며 히트맵을 인위적으로 채우지 않는다.

PCD 전송 예산/송신 성능은 후속 #28 범위다. 이번 검증은 획득·표시와 기존 wire/예산 불변에 한정한다.

TF는 로컬 Actor pose의 시각화이며 실제 ROS TF 수신/방송이 아니다. `Mesh_origin`은 시뮬레이터 원점, Crane은 해측 레일/붐 기준점, Trolley는 실제 모델의 중앙 캐리지, Cabin과 세 LiDAR는 현재 독립 운전실/센서 pose다. 현장 TF 수치가 없어 사진의 좌표계로 실측 정합되었다고 주장하지 않는다. 정적 메시 복제는 표시 변경/운전실 pose revision에서만 재구성하고 충돌·캡처·HWRT에서 제외한다. 원 메시를 가리는 것은 해당 플레이어의 소유 항목에 한정하며 종료/토글 해제에서 복원한다.

검수 추가2026-10-23: 시각화 진입은 측면 근접이며 같은 3개 카메라 버튼을 해치 내려다보기/상부 사선/측면 근접으로 전환한다. 맞춤 대상은 붐·트롤리·그랩·해치 영역이며 전체 선박/안벽을 포함하지 않는다. 고정색은 순수 노랑/빨강/파랑, 높이 옵션은 원료 의미 클래스만 보라 그라데이션으로 바꾸고 나머지는 센서색을 유지한다. 표시용 점 복제본에만 적용하며 원시 point/intensity·PCD는 그대로다. 물리 그랩이 꺼져 있으면 Grab TF/상자도 표시 전용이다. 시각화 진입 때문에 실제 그랩 차폐를 켜지 않는다.
