# C04 — 계획·목록 파일 동선 제안

UXR-P2b 범위의 **제안만**이다. 기준 `d2ca1d1`, [감사 C04](../UXR-AUDIT-1023/RESULT.md)의 권장 범위와 기존 파일 handler를 따른다. 이 문서로 후속 구현을 승인하지 않는다.

감사 E02는 파일 버튼이 선박 상세 아래에 있고 150%에서 경로 끝이 잘리는 장면이다. 파일 읽기까지의 탐색 깊이를 보여 주지만 저장·계획 읽기·목록 읽기의 사용 빈도를 입증하지는 않는다. 이번 입력에 교대별 이용 횟수나 운전원 관찰 기록이 없어 제품의 파일 위치·버튼·경로 입력·저장 방식을 변경하지 않았다.

| 제안 | 보존할 동작 | 후속 확인 |
|---|---|---|
| 기존 파일 버튼과 경로를 왼쪽 앞부분의 `계획·목록` 묶음으로 이동 | 기존 위젯과 클릭 연결을 재사용. 계획 저장/읽기, 슬롯 저장/읽기, 목록 읽기 handler 그대로 | 상세를 열어 스크롤하는 부담이 반복 작업에서 실제로 큰지 확인 |
| 읽기용 경로를 선택·전체 확인 가능하게 표시 | `FileInput`은 기존 계획/목록 읽기 입력. 계획 저장은 기존 `RequestPlanSave` 경로를 사용하며 입력 경로로 저장하게 바꾸지 않음 | 긴 한글/공백 경로, 전체 선택·복사, 저장 후 기존 경로 표시 확인 |
| 저장과 읽기를 같은 묶음 안에서 구별 | 새 파일 선택기·저장 슬롯·동기 I/O·파일 형식·권한 정책 추가 없음 | 기존 저장 완료/읽기 실패 안내, 편집 취소·작업 중단의 기존 동작 확인 |

실행 전 필요한 근거는 교대별 **계획 저장 / 계획 읽기 / 목록 읽기 / 슬롯 저장·읽기 횟수**, 출발 화면, 반복 탐색 여부다. 캡처 수나 코드의 호출 위치를 사용 빈도로 대신하지 않는다. 이를 얻기 위한 새 수집 루프나 사용 기록 기능도 이번에 추가하지 않는다.

후속 구현이 별도 요청되면 같은 client 1920×1080·1280×720, Windows DPI와 UMG scale을 기록하고 글자 100/150%에서 긴 경로·저장/읽기 구별·실패 안내를 직접 확인한다. 기존 위젯 인스턴스와 저장/읽기 계약, 코일 월드의 Slab UI 비노출도 유지한다. 현재 작업의 검증 범위와 직렬 목록은 [RESULT.md](../../../Saved/Reports/UXR-P2b/RESULT.md)를 따른다.
