[Claude → Codex 추가 지시 · 같은 세션 이어서] 측정 주기 성능 개선 (사용자 2026-10-21)

사용자 원문: "1.1 Hz면 너무 낮은 성능인 거 아니야?" — 상단 상태의 센서별 측정 주기가 약 1.1–1.5 Hz. 실제 장비(Mid-360·XT32 등)는 10 Hz급이라 시연에서 실시간성이 떨어져 보인다.
요구:
1. 원인 분석(수치로): 센서별 광선 수 × 주기, 획득 백엔드(CPU 트레이스/GPU depth projection/Auto 중 현재 선택), 충돌 복잡도(이번에 늘어난 GTSU·선박·주름 격벽·원료 메시 충돌), 분석(히트맵·단면·지표) 재계산이 측정 주기에 묶여 있는지, 게임 스레드 대기·작업 스케줄러 상한, 캡처/계측 부하.
2. 목표: 해치 맵 기본 3대 구성에서 **센서별 실제 획득 ≥ 5 Hz(가능하면 프로필 공칭 10 Hz)**, 해치 맵 60 FPS 근방 유지, 150 ms 초과 0. 근거 있는 방법 선택 — 예: 해치 센서에 GPU depth projection 백엔드 사용(정확도 차이 기록), 측정용 충돌 지오메트리 단순화(시각 메시와 분리된 저폴리 충돌: GTSU·선박·격벽), 원료 높이장 기반 해석적 교차(레이-하이트필드)로 원료 히트 계산, 프레임 분할 스캔(time-sliced), 분석은 측정과 분리해 2–5 Hz로, 미리보기 점 예산 조정. 서버 PCD payload는 실제 측정 결과 유지.
3. 화면 상태 표시는 "목표 10 Hz / 실제 n Hz"처럼 구분, 낮으면 원인 툴팁.
4. 검증: 3대 기본 구성·모델별(5종) 실제 Hz 표, 전후 비교, 정확도(높이장 대비 원료 점 오차) 유지, RSS·150 ms·기존 맵 perf 2%.
나머지(호퍼·오버레이·점군 GPU 버퍼 RSS, 기존 HATCH-06 요구·원칙·운영·검증·금지)는 그대로. 중단 시점 작업 트리 변경을 이어서 사용.
